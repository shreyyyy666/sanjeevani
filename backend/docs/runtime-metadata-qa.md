# Runtime metadata QA

The managed preview rendered the public landing page and workspace routes successfully after the Vite/esbuild recovery. The browser navigation to `/workspace/reports` exposed the expected authenticated entry state and reported the route title `Evidence and reports · Sanjeevani` before the auth portal context became active. A subsequent console inspection ran in the auth portal context and returned `title: Login` with canonical `https://manus.im/app-auth`; this is not evidence of the Sanjeevani route canonical value because the browser session redirected to authentication. The current implementation sets canonical URLs from `window.location.origin` plus the SPA route, so the production canonical domain still requires confirmation or an explicit accepted runtime-origin policy.
